##### Асинхронная модель взаимодействия
Это когда продюсер (отправитель) передает сообщение, а консьюмер (получатель) принимает его, когда будет готов, независимо от состояния системы

- продьюсер и консьюмер **НЕ** зависят друг от друга
- масштабируемая система

**Message Broker** - ПО, которое обеспечивает асинхронное взаимодействие

- получает данные от одного компонента системы
- передает данные другому компоненту
- брокер **гарантирует доставку данных / сообщений** даже если произошел сбой во время отправки
- Для брокера **НЕ важно** на каких языках написаны приложения
- хранит сообщения

###### Producer
Отправитель данных

###### Consumer
Получатель данных

###### Message
Сами данные. Сообщение состоит из:
- **Key** - опционально, используется для **маршрутизации** сообщения по разделам
- **Value** - сами данные,почти в любом формате (JSON, Avro, string, etc)
- **Metadata** - timestamp, offset, etc


- **producer** - сериализует (превращает в байты) данные перед отправкой
- **consumer** - десериализует данные при получении

Пример сообщения:
```json
{
    "key": "user123",
    "value": {
        "action": "login",
        "time": "2024-10-01T12:34:56"
    },
    "timestamp": 1696160096000
}
```
